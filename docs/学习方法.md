# 学习方法：这本书为什么这样编排

> 这一页讲的是**怎么用这本书**，以及每个设计背后依据的学习科学结论。
>
> 为什么要把这些说出来，而不是偷偷用？因为**元认知本身就是有效的学习干预**——
> 知道自己为什么在做某个动作，比蒙着头做效果更好。你也可以据此判断哪些机制对你有用、
> 哪些可以跳过。

---

## 一、最短的上手路径

```bash
git clone https://github.com/emmmdty/agent-mem.git
cd agent-mem
pip install -e .
python -m minimem.learn          # 看总览与下一步
python -m minimem.learn next     # 开始第一章
```

课程是正文的**辅助**，不是替代。两种用法都行：

| 你的偏好 | 建议 |
| :--- | :--- |
| 喜欢读长文 | 直接读 `docs/chapterN/`，正文里的 🤔 / ✅ / 🔧 标记就是课程里的那些环节 |
| 喜欢被引导 | 用 `python -m minimem.learn`，它会带你先猜、再跑、再自测 |
| 时间碎片化 | 用课程模式，进度自动保存，`q` 随时退出 |

## 二、七个环节，七条原理

课程（和正文）里的每个环节都对应一条有实证支持的结论。

### 💡 一句话（Motto）—— 组块化

每章开头一句能记住的话，比如第 2 章的「上下文总会满。问题不是会不会丢，而是丢什么。」

**为什么**：工作记忆容量有限。把一章压成一句，你在读后面的细节时有一个挂钩点，不至于读到一半忘了主线。复习时它也是最有效的检索线索。

### 🤔 先猜一猜（Predict）—— 生成效应

在给出结论**之前**先出一道选择题。

**为什么**：这是本书最重要的一个设计。研究一致表明，先尝试回答再看答案（即使答错），记忆效果显著优于直接阅读答案——这叫**生成效应**（generation effect）。而当你猜错时，预期与现实的落差会产生一个「惊讶」，这个惊讶是记忆的强力粘合剂。

**所以本书的预测题刻意设置陷阱**：每道题里都有一个「听起来非常合理但实际是错的」选项，而它往往就是大多数人的直觉。例如：

> 混合检索（dense + BM25）在测试集上的召回率，会不会超过纯 dense？
> A. 会 —— 两路取长补短，融合必然更好
> B. 不会

答案是 B。选 A 不丢人，**选 A 之后你会记住这件事很久**。

> **重要**：猜错不扣分。课程里会统计你的预测正确率，但它的用途是让你知道「哪些地方你的直觉需要校准」，不是打分。

### ▶️ 跑一下（Run）—— 主动实践

每个结论都配一个几秒钟能跑完的脚本。

**为什么**：亲手跑出来的数字，比读到的数字牢固得多。而且本书所有表格都是**实测**的——你在自己机器上跑出的数字应该与正文一致（延迟绝对值会不同，趋势应一致）。

**先说目的，再动手**。每个 Run 环节都会先说「为什么要跑它」和「重点看输出里的哪一处」，否则跑脚本就退化成照着敲命令。

### ✅ 检查点（Recall）—— 提取练习

每节末一道问答题，答案默认折叠。

**为什么**：从记忆里「取」出来，比再「看」一遍有效数倍（**testing effect**，也叫提取练习效应）。这是学习科学里证据最扎实的结论之一，也是最被低估的——大多数人复习时选择重读，因为重读感觉更轻松，而「感觉轻松」恰恰意味着效果差。

所以答案藏在 `<details>` 里。**请先自己想，再展开。**

### 🗣️ 讲给别人听（Explain）—— 费曼技巧

「用三句话向同事解释为什么 RRF 只看名次。」

**为什么**：能读懂和能讲清楚是两种不同的掌握程度。讲不清楚的地方，就是你没懂的地方。

本书不给标准答案，只给一个「合格的解释应该包含什么」的清单。**自评比给答案更有效**——因为对照清单的过程本身就是一次结构化的复述。

### 🔧 动手挑战（Apply）—— 迁移与合意困难

每章末三道题，难度分级：

| 级别 | 类型 | 大约耗时 |
| :--- | :--- | :--- |
| 🟢 | 改一个参数，观察现象 | 5 分钟 |
| 🟡 | 补全一个实现，跑测试验证 | 30~60 分钟 |
| 🔴 | 开放设计，没有唯一答案 | 半天以上 |

**为什么分级**：太简单会无聊，太难会放弃。**合意困难**（desirable difficulty）指的是那种刚好够不着、但努力一下能做到的难度——它带来的长期保留最好。三个级别让你自己选那个「刚好够不着」的。

每道题都写明**做对了会看到什么**。这一点很关键：没有可观察的成功标准，你不知道自己做完没有，很容易半途而废。

### 🚪 下一章预告（Cliff）—— 蔡格尼克效应

每章末留一个本章解决不了的问题。比如第 3 章末：

> 第 1 章的三堵墙，现在推倒了一堵、推远了一堵。**第三堵原封不动**：
> `VectorMemory` 依然会把「星辰银行」和「长风科技」两条矛盾的记忆一起返回。

**为什么**：未完成的任务比已完成的任务更容易被记住（**蔡格尼克效应**）。留一个钩子，你会带着问题进入下一章——而带着问题读，吸收率远高于漫无目的地读。

## 三、间隔复习

```bash
python -m minimem.learn review      # 今天该复习什么
python -m minimem.learn cards ch03  # 看某章的卡片
python -m minimem.learn export-anki # 导出到 Anki
```

用的是 **Leitner 盒子**——间隔重复最简单的形式：

| 盒子 | 下次间隔 | 含义 |
| :--- | :--- | :--- |
| 1 | 1 天 | 刚学会，或刚答错 |
| 2 | 3 天 | |
| 3 | 7 天 | |
| 4 | 16 天 | |
| 5 | 35 天 | 基本记牢了 |

答对升一格，**答错直接回第 1 格**（不做「降一格」的温柔处理——记不住就是记不住，明天再来一次比三天后再来更有效）。

**为什么不用 SM-2 之类更精细的算法**：因为 Leitner 足够好，而且你能看懂它。一个你理解其规则的复习系统，比一个黑箱算法更容易坚持用下去。

**卡片只问「为什么」和「什么时候」，不问「是什么」。** 定义类的知识查得到（而且会过时），判断类的知识查不到。所以你不会看到「BM25 的公式是什么」，而会看到「为什么 2026 年了还要用 BM25」。

## 四、四条降低放弃率的设计

学习材料最常见的失败不是「讲得不好」，而是**读者中途走了**。所以：

**1. 时长诚实。** 每章标注的分钟数是实测的，不是乐观估计。低估时长会让人在预期落空时放弃；而「说好 30 分钟、结果 30 分钟真做完了」会显著提升继续的意愿。

**2. 随时可退。** 课程模式下按 `q` 就走，进度存在 `.learn/progress.json`，回来时 `learn next` 接着上次那一步。这个文件在 `.gitignore` 里，是**你个人的**，不会被提交。

**3. 不惩罚断更。** 连续天数断了就重新从 1 开始，不会显示「你毁掉了 30 天记录」这种话。连续天数是双刃剑——它能提供动力，但断掉时也最容易让人彻底放弃。

**4. 每章都有可运行的产出。** 每章结束时，`minimem` 包里多一个能用的模块，而且能立刻扔进第 10 章的评测 harness 和前面的实现比一比。**看得见的进展**比任何鼓励文案都管用。

## 五、三条推荐路径

| 你的目标 | 路径 | 时间 |
| :--- | :--- | :--- |
| **建立全局观** | 第 1 → 3 → 10 章 | 约 2 小时 |
| **做产品选型** | 第 1 → 3 → 5 → 7 → 10 章，重点读每章末的「代价与选型」 | 约 4 小时 |
| **做研究** | 按顺序通读 + 附录 C 必读清单 + 🔴 级挑战 | 约 15 小时 |

第一条路径是本书刻意设计的**闭环最小系统**：读完你手里就有一个能用的记忆系统，以及一个能测它好坏的工具。这也是本书的写作顺序（先写 1、3、10 章，再补其余）。

## 六、一条重要提醒

本书里有大量「实验结果和直觉不一样」的地方，比如：

- 语义检索在多跳查询上**反而更差**
- 混合检索在小测试集上**没有赢**过纯向量
- 把记忆合并成大块，召回率能刷到 **100%**，而这个 100% 毫无意义

这些不是为了制造反转，而是因为**它们就是跑出来的结果**。本书的原则是如实呈现，包括呈现自己踩过的坑（第 3 章保留了两个真实的性能 bug 及其定位过程）。

所以：**当你的实验结果和某个「常识」冲突时，先怀疑常识。** 这可能是本书最想教给你的一件事。
