# 前言

## 一个让人不安的现象

2023 年以来，几乎每个做 Agent 的人都会经历同一段路：

先是发现模型「记不住事」——上一轮说过的偏好，下一轮就忘了。于是把历史对话全部拼进 prompt。跑了几十轮，token 账单开始难看，模型也开始在长上下文里丢东西。于是上向量库，把历史切片、嵌入、检索。又发现检索回来的片段东一句西一句，模型答得含糊。于是加重排、加摘要、加实体抽取、加知识图谱、加分层……

半年后，系统里堆了六七个组件，每个都在"处理记忆"，但没有人能回答两个问题：

**这些组件各自属于什么范畴？多加一个到底改善了什么？**

**这一整套东西，每处理一条消息花多少钱、多少毫秒？**

这不是个人能力问题。这是这个领域当前的集体状态：概念未收敛，评测不可信，营销词汇的产出速度远超机制创新的速度。

## 这本书想解决什么

三件事。

**第一，给你一套能写进代码的分类法。**

主流综述至少有三套分类轴：有的按「来源 / 形式 / 操作」，有的按「表征 × 操作」，有的按「参数化 / 激活 / 明文」。它们彼此不兼容，连"KV cache 算不算一类独立记忆"都没有共识。

更麻烦的是那套广为流传的心理学四分法——工作记忆、情景记忆、语义记忆、程序记忆。它听起来优雅，但落到代码里往往只是标签：情景记忆 = 带时间戳的对话记录，语义记忆 = 抽出来的事实，程序记忆 = 一个存代码的文件夹。至于从"情景"升格为"语义"的那个**巩固（consolidation）**过程——在大多数系统里根本不是自动发生的，而是你写了一段 prompt 每隔 N 轮手动触发一次。

本书采用 **表征 × 操作 × 载体** 三轴。理由很实际：每一章聚焦一种操作，每一种表征对应不同的代码模块，边界清晰到能画出类图。心理学四分法在第 1 章作为类比出现一次，之后不再作为骨架使用。

**第二，让你对代价有量感。**

本书的每一章都会问同一组问题：写入一条记忆要几次 LLM 调用？检索一次消耗多少 token？相比上一章的方案，延迟是几倍？

这不是洁癖。图记忆方案的检索 prompt 可以轻松达到 10⁴ token 量级；一个"每轮对话都触发反思"的设计，成本可能是朴素方案的十倍。这些数字如果不摆在效果旁边，任何"效果提升 X%"的结论都无法用于决策。

**第三，教你怀疑数字。**

这个领域流传着大量互相矛盾的性能声称。同一个基准上，A 公司说自己 84 分、对手 66 分；对手说 A 公司实际只有 58 分；第三方说两边的评测脚本都跑不出原文数字。而基准本身，被独立审计查出过成规模的答案键错误，以及"答非所问但主题相邻"的回答被自动评判大量放行的问题。

所以本书里所有第三方数字都带标记：📄 论文原文、🏢 厂商自述、⚠️ 存在争议、🕐 时效性内容。你会在第 10 章看到这场争论的完整拆解——那一章的目的不是告诉你谁赢了，而是让你以后能自己判断一个数字值不值得信。

## 这本书不做什么

- **不做框架 API 教程**。Mem0、Letta、Zep、MemoryScope 会作为「某种机制的一个实例」出现，但不会有逐个 API 的用法罗列——那种内容半年就过时，且官方文档写得更准。
- **不排天梯榜**。理由见上。
- **不复现完整规模的基准评测**。第 10 章提供的是一个几分钟能跑完的子集 harness，并会明确说明它能证明什么、不能证明什么。

## 读者对象

你应该：

- 会 Python，能读懂类、抽象方法、类型注解。
- 知道 embedding 和 RAG 是什么，但不要求实现过。
- 有一个 OpenAI 兼容的 LLM API Key（国内的 DeepSeek、通义千问、Kimi 等都可以），或本地能跑一个 7B 以下的小模型。

你不需要有 GPU。除第 9 章（模型编辑）外，全书实验都能在纯 CPU + 一个 API Key 的条件下跑通。这是本书的硬约束：**任何跑不动的示例都不该留在教程里**。

## 怎么读

全书有一条贯穿的主线项目 **MiniMem**。它从第 1 章的一个抽象基类和一个朴素缓冲开始，每章增加一个模块：

```
第 1 章  MemoryStore 接口 + BufferMemory        朴素缓冲
第 2 章  WindowMemory                          滑窗 + sink 保留
第 3 章  VectorMemory                          向量 + 混合检索 + 重排
第 4 章  GraphMemory                           实体图 + PPR 检索
第 5 章  TemporalGraphMemory                   双时间轴 + 事实失效
第 6 章  AgenticMemory                         自组织 note + 动态链接
第 7 章  LayeredMemory                         三层调度 + 换页
第 8 章  SkillMemory                           反思 + 技能库
第 10 章 EvalHarness                           评测 + 成本核算 + 投毒回归
```

所有实现共享同一个接口，所以任意两章的方案都能在同一个 harness 下横向比较。这是本书结构上最重要的设计——**不能被比较的方案，等于没有结论**。

建议的读法：

- **想快速建立全局观**：第 1 → 3 → 10 章。这三章合起来是一个闭环最小系统，读完你能自己搭一个能测的记忆系统。
- **做产品选型**：第 1 → 3 → 5 → 7 → 10 章，重点读每章末尾的「代价与选型」。
- **做研究**：按顺序通读，配合附录 C 的必读论文清单。

每章的结构固定为：**问题 → 机制 → 实现 → 实验 → 代价与选型 → 常见误区 → 参考文献**。如果时间紧，「常见误区」一节的信息密度最高。

## 关于时效性

这本书写于 2026 年年中。有些内容注定会过时：框架的 star 数、各家产品的记忆功能细节、库的 API。这些地方都标了 🕐 和截止日期，并尽量放在可单独更新的表格里（主要是附录 B）。

而机制层面的东西——为什么需要巩固、时间信息缺失会导致什么、图检索为什么贵、投毒为什么难防——变得会慢得多。本书的篇幅重心在后者。
